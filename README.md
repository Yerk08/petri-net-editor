# Petri Net Editor

Легкий и удобный редактор сетей Петри с поддержкой симуляции, сокрытия фрагментов сети и продвинутого анализа.

### [**Открыть в браузере:** https://yerk08.github.io/petri-net-editor/](https://yerk08.github.io/petri-net-editor/)

## 🌟 Особенности

* 🖱️ **Интуитивное управление:** Кнопки и горячие клавиши для режимов курсора, симуляции и сброса.
* 📝 **Гибкое моделирование:** Позиции, переходы, дуги и возможность их скрытия для "горячей" замены структуры во время симуляции.
* ▶️ **Интерактивный лог:** В режиме симуляции позволено менять разметку во время работы, а также ведется история шагов для Вашего анализа.
* 💾 **Экспорт:** Сохранение графов в форматах JSON, их экспорт в SVG и PDF (через Print).
* 🎨 **PWA:** Поддержка Offline-режима, установки как мобильного приложения и темной/светлой темы.
* 🔍 **Распределенный анализ:** Анализ сетей с помощью распределенного кластера, участником которого может стать любой желающий — прямо в браузере (через интерфейс редактора или отдельную страницу [server/worker.html](https://yerk08.github.io/petri-net-editor/server/worker.html)) либо с помощью нативного Python-воркера (инструкция: [server/worker/WORKER_README.md](server/worker/WORKER_README.md)).

## 🛠 Contributing (Разработка)

### 💻📱 Редактор сетей Петри

Для локального запуска проекта достаточно открыть файл `index.html` в браузере или запустить локальный сервер:

```bash
python3 -m http.server 8000
```

⚠️ **Важно для разработчиков:** При редактировании кода на `localhost` обязательно закомментируйте или временно удалите в самом низу файла `index.html` скрипт, подключающий `sw.js` (Service Worker). В противном случае браузер закеширует старую версию приложения, и вы не увидите изменения в коде до полной очистки кеша.

Всё поведение протестировано вручную, и, поскольку сложной бизнес-логики работы в приложении нет, автоматических тестов по сути тоже нет. В директории `client/tests`, вы можете запустить следующую команду:
```bash
npm run test
```

### 🗄️ Сервер распределенного анализа

Для тяжелых расчетов (графы достижимости, поиск тупиков и др.) реализован распределенный кластер на базе **Go, Lua, WebAssembly (WASM) и Python (Numba)** с серверной проверкой результатов (**BFT**).

#### Запуск кластера
Перейдите в директорию `server/` и поднимите мастер-сервер, раздачу WASM-окружения и вычислительный воркер одной командой:

```bash
cd server
docker compose up --build -d
```

#### Подключение только в качестве вычислительного узла (Worker)
Если вы хотите лишь помочь кластеру с вычислениями без развертывания своего сервера:
* **В браузере (WASM):** откройте [server/worker.html](https://yerk08.github.io/petri-net-editor/server/worker.html) (или используйте панель **«Помощь кластеру»** в режиме Диспетчера основного редактора). Для стабильной работы браузерного узла при выключенном экране на смартфоне включите галочку **«🔋 В фоне»** и отключите оптимизацию батареи для браузера в настройках телефона.
* **На ПК (Python / Docker):** следуйте руководству в [server/worker/WORKER_README.md](server/worker/WORKER_README.md).

#### Разработка собственных алгоритмов
Алгоритмы подключаются как плагины в директории `server/algorithms/` (поддерживается горячая загрузка и выгрузка при изменении или удалении папок). Каждый пакет состоит из трёх файлов:
* `meta.json` — описание алгоритма, входных параметров и лимитов.
* `orchestrator.lua` — сценарий разбиения задачи на чанки, BFT-проверки и сборки отчета.
* `worker_algo.py` — вычислительная функция `run_chunk(raw_data)` для выполнения на воркерах.

Готовые заготовки и подробные комментарии по написанию собственных алгоритмов находятся в шаблонах:
* `server/algorithms/_example/` — рабочий пример алгоритма.
* `server/algorithms/_template_init/` — стартовый шаблон с развернутыми комментариями.
* `server/algorithms/_template_minimal/` — минимальный каркас плагина.

Спецификация API кластера описана в [server/openapi.yaml](server/openapi.yaml), а архитектурные детали — в [docs/distributed-analysis.md](docs/distributed-analysis.md).
